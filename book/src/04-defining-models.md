# Defining Models: Node & Edge

## Node Derive
Annotate a struct with `#[derive(Node)]` and provide a table name:
```rust
#[derive(Node)]
#[junction(table = "person")]
struct Person { name: String, age: i32 }
```
If omitted, the table name is generated by converting the type name to snake_case.

### Auto `id` Column
Even if you omit an `id` field, the schema exposes `schema().id` as a typed `Col<SimpleId<Person>>`.

## Edge Derive
Edges require both source and target annotations:
```rust
#[derive(Edge)]
#[junction(table = "knows")]
struct Knows {
    #[junction(source)]
    src: SimpleId<Person>,
    #[junction(target)]
    dst: SimpleId<Person>,
    strength: i32,
}
```
If you omit `in` / `out` / `id` fields, they are synthesized; if you include custom names, they are recorded.

## Custom Endpoint Names
You can use semantic names like `from_user` and `to_user`. The adapter maps them internally while preserving your field names in deserialized results.

## Schema Generation Algorithm
For each non-id field, the macro creates a `Col<T>` with `table` and column name. The table name is stored as `TABLE`. The schema struct name is a module named after the table (`person::Schema`).

## Insertable Trait
`Node` derive also implements `Insertable` and `HasTableName` automatically.

## Tips
- Keep Node structs lean, avoid business logic.
- Prefer explicit table names for stability across refactors.
- Use consistent casing for columns; snake_case recommended.
